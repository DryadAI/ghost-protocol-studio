# THE GHOST PROTOCOL — project context for Claude

AI debate show studio for a YouTube channel. AIs debate each other (and riff with human co-hosts) in four formats; episodes render to video with a fully open-source pipeline.

## Owner and environment
- Owner: Nathan (DryadAI). Arch Linux. Editor: micro. Open-source and free-tier only — never suggest paid/closed tools.
- Machines: **madhatter** runs the Bifrost LLM gateway (http://localhost:8080/v1, OpenAI-compatible, free-tier keys mapped inside) and hosts the studio. **precision** accesses it over LAN.
- Free-tier fallbacks if Bifrost is down: Groq (`https://api.groq.com/openai/v1/chat/completions`), Gemini OpenAI-compat endpoint.

## Architecture — read before changing anything
- `ghost_protocol_studio.py` is a **single self-contained file, Python 3 stdlib only. No pip dependencies, ever.** Server = ThreadingHTTPServer; the entire front-end (CSS/HTML/JS) lives in the `HTML` string. Keep it that way.
- **The show runs on the server** (phase 2). `build_plan` plans the turns, `run_episode` executes them on a thread, and every event is appended to the episode's bus. Human turns block that loop on a `threading.Event` until `POST /api/episode/input`. The browser is a **tailer**: it polls `GET /api/episode/<id>/bus?from=N` and draws what comes back, so closing the tab mid-run does not stop the episode. Routes: `/api/chat`, `/api/ping`, `/api/models`, `/api/topics`, `/api/defaults`, `/api/characters`, `/api/cast`, `/api/voices`, `/api/render`, `/api/episodes`, `/api/episode/*`, plus a path-traversal-guarded `/assets/<path>` (portraits and voiceprints).
- **An episode is a directory** (phase 2): `<show>/episodes/ep-NNN/` holds append-only `bus.jsonl` (`{seq,ts,from,to,type,ref,body}`), `episode.json` (state/cast — **never credentials**, those stay in `Episode.runtime`), and `transcript.json`, which is *derived* by replaying the bus. Edits, cuts and re-rolls are `note`/`retake` events, never mutations — a cut line stays in history and just leaves the cut. State machine: `brief → running → awaiting_human → post → rendered`.
- **Hired souls** (phase 1). A show dir resolves as `$GP_SHOW_DIR` → `./show` → the parent dir (that last one is how the vendored `show-template/studio/` copy finds its show). `scan_show()` reads `cast/<sid>/` and `crew/<sid>/` Guild packages; `assemble_prompt()` turns each `SOUL.md` — plus this show's `MEMORY.md` as a continuity digest — into a system prompt. Rescanned per request, so **↻ RELOAD SOULS** picks up edits with no restart.
- **Chairs, not sids.** `FORMAT_SLOTS` (Python, served on `/api/cast` so the casting picker and the headless runner share one definition) gives each format its chairs; a hire qualifies via `card.json` `formats`+`role`. Plans always address chairs, so recasting never touches them. An unfilled chair falls back to the built-in cast via `builtin_members()`.
- **Crew agents work on the bus.** SPLICE (phase 3.1) reads the finished cut and emits `approval_request` cut proposals with one-word justifications; nothing is removed until a human approves, and the survivors become the locked cut. Each crew agent performs under its soul from `<show>/crew/<sid>/`, so hiring a different editor changes the notes.
- `characters.json` is the design-intent master registry for the 13 cast members (archetype, humor style, one unique model each — Ollama + Groq only, no vllm/* or paid models). It is also the engine's fallback cast for chairs nobody was hired into. `CASTS` in the embedded JS is the browser-side equivalent, kept in sync by hand. Portraits (transparent cutouts) live in `assets/`. See CHARACTER_REGISTRY.md.
- `topics.json` (1000 theses: 500 `serious` / 500 `absurd`) is generated by `gen_topics.py` (seeded, deterministic). Regenerate rather than hand-editing; add topics by extending the seed lists/grammars.
- **Voices**: two TTS engines behind one switch (03 // ENGINE). `omnivoice` (default) clones each speaker's designed voiceprint from `assets/voices/<sid>.wav`; `piper` reads local `.onnx` models and is the offline fallback. `synth_segment()` picks between them per line and always falls back to piper rather than losing a render. The OmniVoice client (`ov_*` functions, stdlib urllib against a Gradio queue+SSE API) lives in `ghost_protocol_studio.py` because the renderer needs it and the file must stay self-contained; `voice_forge.py` imports it.
- Voiceprints are **committed assets, not build output** — `assets/voices/*.wav` is un-ignored on purpose. Design intent is `characters.json` → `omnivoice` (per character) and `guest_voices` (co-hosts, star witness). The wav on disk wins over the spec once approved. Re-roll one with `python3 voice_forge.py design --sid <sid>`; never hand-edit a wav.
- The design model is stochastic — attributes steer it, they don't pin it. Always run `voice_forge.py verify` after touching voices: it measures actual pitch and fails if two speakers sharing a format land within 12 Hz. `design` picks the best of N takes by that same metric.
- Export produces `compile_show.sh`: same two engines (`TTS=piper` forces the offline one) + ffmpeg drawtext segments concatenated into `episode.mp4`. Renderer must stay 100% open source.

## Show formats (cast sids in parentheses)
1. `socratic` — alpha interrogates beta, kernel verdict.
2. `roundtable` — p7/mira/cynic + 0-3 humans injecting banter between rounds; kernel awards Best Line.
3. `tribunal` — pros/def/acc, openings → N examinations → closings → kernel ruling → human jury. Optional star witness (checkbox in 01 // FORMAT) with name/background/voice fields.
4. `triad` — stoic/nihil/util rounds → synth compromise.

## Conventions
- Aesthetic: dark terminal (`#0a0e14` bg, alpha red `#ff5555`, beta green `#50fa7b`, human yellow, kernel purple), monospace, ALL-CAPS labels with `// section` headers. Keep new UI in this voice.
- Speaker entries carry `{sid,name,color,hex,voice,ovoice,human,text,inst}` — `hex` feeds ffmpeg, `inst` enables RE-ROLL, `voice` is the piper model and `ovoice` the OmniVoice voiceprint sid. Preserve these fields.
- Simulation Mode must keep working with zero network calls after any engine change.

## Commands
```bash
python3 ghost_protocol_studio.py                    # dev (localhost:7860)
GP_BIND=0.0.0.0 python3 ghost_protocol_studio.py    # LAN (madhatter)
GP_SHOW_DIR=/path/to/show python3 ghost_protocol_studio.py   # run someone else's show
python3 ghost_protocol_studio.py --run --sim --format triad --topic "..."   # headless, no browser
python3 ghost_protocol_studio.py --episode ep-004 --run       # re-run an episode's brief
python3 -m py_compile ghost_protocol_studio.py      # syntax gate — run after every edit
python3 gen_topics.py                               # regenerate topics.json
python3 voice_forge.py design                       # design missing voiceprints
python3 voice_forge.py verify                       # voice-distinctness gate — run after any voice change
python3 voice_forge.py audition                     # whole cast in one wav, for listening
bash compile_show.sh                                # render episode.mp4 (needs ./voices/)
```
Test checklist after changes: py_compile passes; `curl localhost:7860/` → 200; `/api/topics` → 1000; `/api/voices` lists 17 voiceprints; a Simulation Mode run completes end-to-end in each touched format — via the UI *and* headless, since they take different paths into the same runner. After voice changes also: `voice_forge.py verify` passes, and a 3-segment `POST /api/render` with `engine:"omnivoice"` returns `ok:true`.
